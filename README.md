# claude-bridge

**Русский** | [English](README.en.md)

Локальный прокси с API Anthropic Messages. Через него Claude Code работает на других моделях:

- **Codex** — GPT-5.6 Sol / Terra / Luna и GPT-5.5 по подписке ChatGPT (вход через браузер или токены Codex CLI);
- **OpenAI API** — по `OPENAI_API_KEY`;
- **OpenAI-compatible** — OpenRouter, Ollama, vLLM, LM Studio, DeepSeek и другие Chat Completions API;
- **Anthropic API** — по `ANTHROPIC_API_KEY`.

Claude Code шлёт запросы на `http://127.0.0.1:17870/v1/messages`. Прокси переводит их в формат провайдера и возвращает ответ в виде SSE в формате Anthropic. Поддерживаются стриминг и обычные ответы, tool use, картинки, блоки thinking и встроенный веб-поиск провайдера. Модель можно сменить посреди сессии через `/model`, а для всех сессий сразу — из CLI или UI. Ненужных провайдеров можно отключить, а проксирование — разрешить только из выбранных стран.


## Установка

Готовые сборки лежат в [Releases](../../releases). Для каждой версии там есть:

| Файл | Что внутри |
| --- | --- |
| `claude-bridge-<версия>-linux-x64.tar.gz` | UI и CLI |
| `claude-bridge-<версия>-macos-universal.zip` | `claude_bridge_ui.app`, CLI внутри `Contents/MacOS` |
| `claude-bridge-<версия>-windows-x64.zip` | UI и `claude-bridge.exe` |
| `claude-bridge-cli-<версия>-<платформа>.*` | только CLI |
| `SHA256SUMS.txt` | контрольные суммы |

Нужен установленный [Claude Code](https://docs.claude.com/en/docs/claude-code) (`claude` в `PATH`).

Сборки не подписаны:
- **macOS.** При первом запуске откройте приложение через правый клик → «Открыть» или снимите карантин: `xattr -dr com.apple.quarantine claude_bridge_ui.app`.

Только CLI из исходников:

```bash
cargo install --path cli
```

## CLI

```bash
claude-bridge codex          # Claude Code на GPT-5.6 Sol (вход в ChatGPT при первом запуске)
claude-bridge openai         # OpenAI API, нужен OPENAI_API_KEY
claude-bridge anthropic      # Claude Opus: вход Claude Code или ANTHROPIC_API_KEY
```

Команда поднимает прокси в фоне (или берёт уже запущенный) и запускает `claude`, направленный на него. Флаги:
- `-d` — передать в Claude Code `--dangerously-skip-permissions` (по умолчанию выключено: Claude Code спрашивает разрешения как обычно). Флаг действует только на сессию, которую запускает эта команда в терминале. Расширение для IDE и обычный `claude` запускаются без claude-bridge, поэтому режим разрешений для них выбирается в самом расширении или через `permissions.defaultMode` в `~/.claude/settings.json`;
- `--restart` — перезапустить прокси;
- всё после имени маршрута уходит в `claude` как есть.

Прокси — отдельный процесс, общий для всех сессий. Он работает и после выхода из Claude Code.

| Команда | Что делает |
| --- | --- |
| `claude-bridge status` | состояние прокси, входов и ключей |
| `claude-bridge connect` / `disconnect` | прописать прокси в `~/.claude/settings.json`, чтобы через него шёл любой `claude`, или убрать его оттуда |
| `claude-bridge usage` | [лимиты подписок](#лимиты-подписок): Claude, ChatGPT |
| `claude-bridge stop` | остановить прокси |
| `claude-bridge login codex` | войти в ChatGPT через браузер |
| `claude-bridge logout codex` | удалить сохранённые токены |
| `claude-bridge model terra@max` | переключить все запущенные сессии на модель |
| `claude-bridge model --clear` | вернуть выбор модели через `/model` |
| `claude-bridge model --list` | список коротких имён |
| `claude-bridge serve` | запустить прокси на переднем плане |

## Модели

В Claude Code модель выбирается через `/model <имя>`. Короткие имена:

| Имя | Модель |
| --- | --- |
| `sol` (`codex`, `cx`) | `codex-oauth:gpt-5.6-sol`, усилие high |
| `terra`, `luna`, `gpt55` | GPT-5.6 Terra, GPT-5.6 Luna, GPT-5.5 |
| `fast` / `smart` / `deep` / `xhigh` / `max` | Sol с усилием low / medium / high / xhigh / max |
| `opus`, `anthropic:sonnet`, `anthropic:haiku` | Claude: через вход Claude Code или по `ANTHROPIC_API_KEY` |

На вкладке **«Модели»** встроенные модели показаны вместе с пользовательскими. Новую модель Claude, GPT или OpenAI-compatible можно добавить без перекомпиляции: задаются название, провайдер, Model ID и необязательное усилие. Пользовательские модели и модель, выбранная на главной странице, хранятся в `~/.claude-bridge/models.json`. Отключённый провайдер скрывает свои модели из списков, но не удаляет их.

Ещё варианты:
- **Суффикс усилия.** `@low|medium|high|xhigh|max` работает с любой моделью, например `/model terra@max` или `/model luna@low`.
- **Явный провайдер.** `провайдер:модель`, где провайдер — `codex-oauth`, `openai`, `openai-compat` или `anthropic`. Для совместимого API: `/model openai-compat:llama3.3`.
- **Имя без провайдера** уходит текущему провайдеру как есть.

Claude Code сам делает служебные запросы к `claude-haiku-*` и `claude-sonnet-*`: заголовки, сабагенты, проверки. Прокси отправляет их провайдеру основной модели сессии на его быструю модель, с усилием low для `haiku` и medium для `sonnet` (каждый такой вызов несёт весь системный промпт Claude Code, около 37K токенов), поэтому ключ Anthropic для них не нужен. `claude-opus-*` идёт на основную модель с усилием сессии. Усилие задаётся только моделью: суффиксом `@…`, коротким именем или сохранённой моделью; без него — medium, как по умолчанию в API. В Claude они идут, только если основная модель сессии — Claude (`anthropic:…`).

### Claude и другие модели в одной сессии

Прокси сам в Claude по подписке не входит: условия Anthropic разрешают токены подписки только в её собственных приложениях. Вместо этого Claude Code пользуется своим входом, а прокси только пересылает его запросы.

- Если Claude Code вошёл (`/login`, по подписке или по ключу), `claude-bridge` его вход не трогает. Иначе Claude Code получает заглушку `ANTHROPIC_AUTH_TOKEN=claude-bridge`: с ней он не просит войти, весь трафик идёт к другим провайдерам, а модели Claude работают по `ANTHROPIC_API_KEY`.
- Claude выбирается явно: `/model opus` (`claude-bridge` направляет его на `anthropic:claude-opus-5-5`), `anthropic:sonnet` или `anthropic:haiku`. Запросы уходят прямо в Anthropic с входом Claude Code. Прокси пересылает их как есть и ничего не сохраняет.
- `/model sol`, `terra` и другие модели работают через прокси, как обычно.
- Служебные запросы Claude Code (`claude-haiku-*`, `claude-sonnet-*` и т. п.) идут туда же, куда основная модель **этой** сессии. Пока выбрана не Claude, в Anthropic из сессии не уходит ни одного запроса. Сессии различаются по заголовку `X-Claude-Code-Session-Id` и друг на друга не влияют.
- Закреплённая модель («Модель для всех сессий») важнее всего.

Чтобы через прокси шёл и обычный `claude` (и расширения для IDE), выполните `claude-bridge connect` или включите «Любой claude через прокси» на главной в UI. В `~/.claude/settings.json` добавится:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:17870",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "anthropic:claude-opus-5-5",
    "ANTHROPIC_AUTH_TOKEN": "claude-bridge"
  }
}
```

`ANTHROPIC_AUTH_TOKEN` добавляется, только если Claude Code не вошёл сам: без него Claude Code и расширение для IDE просят войти, даже когда работают на GPT. Токен из `env` важнее подписки, поэтому после `/login` заглушка убирается, а после выхода — возвращается (UI следит за этим постоянно, CLI — при каждом запуске `claude-bridge <маршрут>`). Свой `ANTHROPIC_AUTH_TOKEN` не трогается.

Остальное содержимое файла не меняется. `claude-bridge disconnect` (или тот же переключатель) убирает только добавленные строки. Пока прокси не запущен, такой `claude` работать не будет.

## Провайдеры

На вкладке «Провайдеры» каждую группу можно отключить: Anthropic (Claude), ChatGPT / Codex, OpenAI API, OpenAI-compatible. Отключённый провайдер:
- пропадает из UI: аккаунтов, лимитов, списка моделей, настроек и журнала запросов; его лимиты не запрашиваются;
- не может быть выбранной моделью, с которой UI запускает прокси;
- блокируется прокси: на запрос к нему (например, `/model sol`) приходит ошибка 400 с подсказкой.

Входы и ключи при этом сохраняются. Список хранится в `CLAUDE_BRIDGE_DISABLED_PROVIDERS` (`anthropic`, `codex`, `openai`, `openai-compat` через запятую) и применяется сразу, без перезапуска.

## Маршруты: выходы и страны

Вкладка «Маршруты» — конструктор: для каждого провайдера выбирается, **через что** идёт его трафик и **из каких стран** его можно отправлять.

**Выходы.** Кроме прямого соединения можно добавить:
- `ssh://user@host[:port]` — свой сервер. Прокси сам поднимает туннель `ssh -D` (локальный SOCKS5) и держит его, пока работает. На сервере нужен только `sshd` с входом по ключу. Вход должен работать без пароля и вопросов: `ssh-copy-id user@host`, затем проверьте `ssh user@host`. Ключ берётся как обычно: `~/.ssh`, ssh-agent, `~/.ssh/config`. На сервере нужно `AllowTcpForwarding yes`, в Fedora это включено по умолчанию;
- `socks5://host:port`, `http://[user:pass@]host:port` — готовый прокси, например локальный SOCKS-порт VPN-клиента.

У каждого провайдера (Anthropic, ChatGPT / Codex, OpenAI API, OpenAI-compatible) свой выход. Если выход недоступен (туннель не поднялся, прокси не отвечает), запрос **не уходит напрямую**, а отклоняется с ошибкой 502. **DNS.** Через SOCKS и SSH имена разрешаются на дальней стороне (`socks5h`), HTTP-прокси получает имя в `CONNECT`. Для прямого соединения и для адреса самого SSH-сервера прокси, UI и CLI спрашивают DNS over HTTPS: серверы из `CLAUDE_BRIDGE_DOH_SERVERS`, по умолчанию `https://1.1.1.1/dns-query`, запасной `https://8.8.8.8/resolve`. Хост сервера должен быть задан IP, чтобы для обращения к нему не нужен был DNS. Системный резолвер, роутер и провайдер интернета имён не видят. Имя SSH-сервера берётся после `~/.ssh/config` (`ssh -G`), его IP передаётся в `ssh` через `HostName`, а `HostKeyAlias` сохраняет проверку `known_hosts` по имени. Если DoH не отвечает, запрос не уходит, на системный DNS прокси не переключается. `CLAUDE_BRIDGE_DNS=system` возвращает обычный резолвер: это нужно, если VPN-клиент маршрутизирует по доменам через fake-ip DNS (с DoH он увидит только IP; проверка страны всё равно не пропустит запрос не туда).

**Страны.** Когда ограничение включено, прокси перед каждым запросом, без кэша, спрашивает у хоста провайдера страницу Cloudflare `/cdn-cgi/trace` **через выход этого провайдера**. Это `api.anthropic.com`, `chatgpt.com` или `api.openai.com`. Ответ показывает IP и страну так, как их видит сам провайдер. Домен тот же, что у настоящего запроса, поэтому правила маршрутизации по доменам в VPN-клиенте или на роутере действуют на проверку так же. Если у хоста такой страницы нет (часто у OpenAI-compatible), спрашивается `www.cloudflare.com` через тот же выход: за SSH-сервером или прокси это точно, напрямую — приблизительно. У провайдера может быть свой список стран, иначе действует общий. Если страна не разрешена или не определена, прокси ничего не отправляет провайдеру и возвращает 451 с хостом, IP и страной. Приложение показывает об этом уведомление.

**Остальной трафик Claude Code.** Кроме запросов к модели Claude Code сам ходит в сеть: обновляет OAuth-токен, запрашивает профиль и лимиты, подключается к MCP-серверам по HTTP, выполняет WebFetch, запускает команды (git, npm, curl). Чтобы и это не уходило с настоящего адреса:
- прокси открывает второй порт (по умолчанию порт прокси + 1, `CLAUDE_BRIDGE_EGRESS_PORT`, `0` — выключить) — HTTP-прокси с `CONNECT`. Каждое соединение идёт **через выход Anthropic и с его проверкой страны**. Успешная проверка действует 15 секунд, потому что команды вроде `npm install` открывают сотни соединений. Отказ — 451 или 502 с причиной, запись в журнале и уведомление, напрямую ничего не уходит;
- Claude Code получает `HTTPS_PROXY` и `HTTP_PROXY` на этот порт, `NO_PROXY=127.0.0.1,localhost,::1` (сам мост — напрямую) и `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (без телеметрии, отчётов об ошибках и проверки обновлений; Claude Code обновляется вручную). При `claude-bridge <маршрут>` это переменные окружения сессии, при «любом claude через прокси» — `env` в `~/.claude/settings.json`. Мост помечает свои ключи в `CLAUDE_BRIDGE_MANAGED`: обновляет и убирает только их, а заданный вами `HTTPS_PROXY` не трогает (тогда этот трафик идёт через ваш прокси).

Сам прокси переменные `HTTPS_PROXY` и `HTTP_PROXY` не читает: куда идёт трафик, решают выходы.

**IPv6.** Если VPN туннелирует только IPv4, `CLAUDE_BRIDGE_IPV6=0` оставляет только IPv4: и для имён (DoH отдаёт только A-записи), и для сокетов.

**Что прокси закрыть не может — делайте сами.**
- **Вход через браузер** (вход в ChatGPT, `claude /login`). Страница входа идёт маршрутом браузера, мост её не видит. VPN прячет только IP: через JavaScript страница видит часовой пояс и язык браузера (`Accept-Language`). Перед входом включите VPN и выставьте в браузере пояс и язык страны выхода, удобнее в отдельном профиле.
- **Обновление Claude Code.** С `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` автообновление выключено. `claude update` из обычного терминала скачивает новую версию с серверов Anthropic с настоящего адреса. Запускайте его через порт прокси: `HTTPS_PROXY=http://127.0.0.1:17871 claude update` (или из сессии Claude Code, где переменная уже задана).
- **Содержимое запросов.** Системный промпт Claude Code содержит платформу, версию ОС и путь рабочей папки (а с ним имя пользователя), git status с автором коммитов. Плюс язык переписки. Время в коммитах и вывод команд выравнивают `CLAUDE_BRIDGE_TZ` и `CLAUDE_BRIDGE_LANG`.
- **Аккаунт.** Страна регистрации, карта оплаты, вход в тот же аккаунт с других устройств без VPN, время активности.

На главной показана страна прямого соединения, а под ней — какие провайдеры сейчас блокируются.

Настройки применяются сразу, без перезапуска:

| Переменная | Назначение |
| --- | --- |
| `GEO_GUARD_ENABLED` | `1` — проверять страну |
| `GEO_ALLOWED_COUNTRIES` | общий список: коды ISO через запятую (`DE,NL,SE`); `-` — ни одной; без значения — все из списка |
| `GEO_ALLOWED_<ПРОВАЙДЕР>` | свой список провайдера: `GEO_ALLOWED_ANTHROPIC`, `_CODEX`, `_OPENAI`, `_OPENAI_COMPAT` |
| `CLAUDE_BRIDGE_EXITS` | выходы через запятую: `ssh://root@203.0.113.7,socks5://127.0.0.1:1080` |
| `CLAUDE_BRIDGE_EGRESS_PORT` | порт для остального трафика Claude Code; по умолчанию порт прокси + 1, `0` — выключить |
| `CLAUDE_BRIDGE_TZ` | часовой пояс (`TZ`) для Claude Code и запускаемых им команд: время в git-коммитах, `date`. `auto` — пояс страны выхода Anthropic (пока страна неизвестна — `UTC`), или явно: `UTC`, `Europe/Berlin`; пусто — системный |
| `CLAUDE_BRIDGE_LANG` | язык (`LANG`, `LC_ALL`) для Claude Code и запускаемых им команд: их вывод уходит модели на этом языке. Например `en_US.UTF-8` или `C.UTF-8`; пусто — системный |
| `CLAUDE_BRIDGE_IPV6` | `0` — только IPv4 |
| `CLAUDE_BRIDGE_EXIT_<ПРОВАЙДЕР>` | выход провайдера, например `CLAUDE_BRIDGE_EXIT_CODEX=ssh://root@203.0.113.7`; без значения — напрямую |

Список стран задан в `COUNTRIES` в [core/src/geo.rs](core/src/geo.rs).

## Лимиты подписок

`claude-bridge usage` и вкладка «Аккаунты» показывают, сколько израсходовано в каждом окне лимита и когда оно сбросится:

| Провайдер | Откуда данные |
| --- | --- |
| Claude | заголовки `anthropic-ratelimit-unified-*` из ответов Anthropic на запросы Claude Code; прокси запоминает последние в `~/.claude-bridge/claude-usage.json`. Появляются после первого запроса к Claude через прокси |
| ChatGPT / Codex | `chatgpt.com/backend-api/wham/usage`, тот же запрос, что делает `/status` в Codex CLI |

UI обновляет лимиты раз в минуту и по кнопке.

Когда ChatGPT отвечает 429 `usage_limit_reached`, прокси запоминает время сброса и до него отвечает сам, не отправляя разговор наверх; Claude Code получает `x-should-retry: false` и не повторяет запрос. UI предупреждает уведомлением и значком в трее, когда лимит исчерпан, когда пятичасовое окно Claude или Codex израсходовано на 80% и когда при текущем темпе его не хватит до сброса.

Там же видны сведения о подписках. Для ChatGPT это план и дата окончания платной подписки из ID-токена. Для Claude — план, дата начала и способ оплаты из `~/.claude.json`: даты окончания Claude Code не хранит. В CLI это показывает `claude-bridge status`.

## UI

Приложение на Flutter — панель управления тем же фоновым прокси:
- **Главная**: местоположение прямого соединения (IP, страна, флаг) и какие провайдеры блокируются, запуск и остановка прокси (по умолчанию он запускается вместе с приложением), подключение любого `claude` к прокси, модель для всех сессий;
- **Провайдеры**: какие провайдеры используются ([подробнее](#провайдеры));
- **Аккаунты**: все провайдеры в одном месте: вход Claude Code, вход через браузер для ChatGPT, API-ключи OpenAI и Anthropic, лимиты подписок;
- **Запросы**: живой журнал запросов с моделью, временем, токенами (вход / из кэша / выход) и ошибками;
- **Маршруты**: выходы (напрямую, SSH-сервер, прокси) и разрешённые страны для каждого провайдера ([подробнее](#маршруты-выходы-и-страны));
- **Настройки**: редактор `~/.claude-bridge/.env`.

Уведомления появляются тостами в правом нижнем углу, а их история открывается кнопкой в шапке: фильтр по типу, копирование текста.

Язык интерфейса — русский или английский — переключается кнопкой `RU` / `EN` в шапке. По умолчанию берётся язык системы.

UI ищет CLI в таком порядке: рядом со своим исполняемым файлом, в `~/.cargo/bin`, в `PATH`. Путь можно задать в настройках.

Обычный порядок работы: включить на главной «Любой claude через прокси», затем запускать `claude` в любом терминале или IDE и переключать модели через `/model` или закрепление.

## Настройки

Всё хранится в `~/.claude-bridge/` (другую папку можно задать через `CLAUDE_BRIDGE_HOME`):
- `.env` — ключи и параметры;
- `codex-oauth.json` — токены, права `0600`;
- `proxy.log` — лог прокси.

Переменные окружения важнее `.env`. После изменения настроек перезапустите прокси: `claude-bridge stop` или кнопка в UI. Исключение — провайдеры и маршруты: прокси перечитывает их на каждом запросе.

| Переменная | Назначение |
| --- | --- |
| `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | ключи для маршрутов по API |
| `OPENAI_COMPAT_BASE_URL` | адрес OpenAI-совместимого API; `/chat/completions` добавляется автоматически |
| `OPENAI_COMPAT_API_KEY` | необязательный ключ OpenAI-совместимого API |
| `~/.claude-bridge/models.json` | пользовательские модели и модель, выбранная в UI |
| `CLAUDE_BRIDGE_PORT` | порт прокси, по умолчанию `17870` |
| `CLAUDE_BRIDGE_CONTEXT_WARN_TOKENS` | с какого размера контекста на запрос UI предупреждает значком в трее и уведомлением; по умолчанию `150000`, `0` отключает |
| `CODEX_REASONING_SUMMARY` | `auto` / `concise` / `detailed` / `none` |
| `CODEX_TEXT_VERBOSITY` | `low` / `medium` / `high` |
| `CODEX_CONTEXT_WINDOW_TOKENS`, `CODEX_AUTO_COMPACT_WINDOW_TOKENS`, `CODEX_DISABLE_COMPACT` | окно контекста (372K) и порог автосжатия (по умолчанию 200K), которые `claude-bridge codex` сообщает Claude Code. Порог также пишется в `~/.claude/settings.json` (`CLAUDE_CODE_AUTO_COMPACT_WINDOW`) для «любого claude через прокси». Каждый вызов инструмента заново отправляет весь контекст, кэшированный или нет, поэтому раннее сжатие заметно экономит лимит |
| `CODEX_PARALLEL_TOOL_CALLS` | `0` — один вызов инструмента за ход; по умолчанию несколько, это меньше ходов и меньше повторных отправок контекста |
| `CODEX_DISABLE_REASONING_CACHE` | `1` — не передавать зашифрованные рассуждения в следующий ход |
| `ANTHROPIC_UPSTREAM_URL` | другой адрес Anthropic API |
| `CLAUDE_BRIDGE_BIN` | путь к CLI для UI |
| `CLAUDE_BRIDGE_AUTOSTART` | `0` — UI не запускает прокси при открытии |
| `CLAUDE_BRIDGE_LANG` | язык UI: `ru` или `en` |
| `CLAUDE_BRIDGE_DISABLED_PROVIDERS` | отключённые провайдеры: `anthropic`, `codex`, `openai`, `openai-compat` через запятую |
| `GEO_*`, `CLAUDE_BRIDGE_EXIT*` | [маршруты и страны](#маршруты-выходы-и-страны) |
| `CLAUDE_BRIDGE_DNS` | `doh` (по умолчанию) или `system`: как разрешать имена, [подробнее](#маршруты-выходы-и-страны); после перезапуска прокси |
| `CLAUDE_BRIDGE_DOH_SERVERS` | серверы DoH через запятую, по порядку: JSON API (`application/dns-json`), хост — IP; по умолчанию `https://1.1.1.1/dns-query,https://8.8.8.8/resolve` |
| `CLAUDE_BRIDGE_LOG` | фильтр логов, например `claude_bridge_core=debug` |

**Вход в ChatGPT.**
- Если у вас уже есть `~/.codex/auth.json` от Codex CLI, прокси использует эти токены. Обновлённые токены записываются обратно туда же, чтобы Codex CLI продолжал работать.
- Собственный вход слушает `localhost:1455`, как и Codex CLI, поэтому одновременно с `codex login` он не запустится.

## Безопасность

- Прокси слушает только `127.0.0.1`.
- Запросы, у которых заголовок `Host` не равен `127.0.0.1:<порт>` или `localhost:<порт>`, отклоняются. Это защита от DNS rebinding: веб-страница не может пользоваться вашими подписками через прокси.
- Управляющие эндпоинты (`/_model`, `/_shutdown`, `/_exits`) требуют заголовок `x-claude-bridge`. Браузер не отправит его с чужого сайта без CORS preflight.
- Страну определяет только Cloudflare: `/cdn-cgi/trace` у хостов провайдеров и у `www.cloudflare.com`. UI спрашивает раз в минуту, прокси — перед каждым запросом, пока включено ограничение. Сторонние geo-IP сервисы не используются.
- SSH-туннели запускаются с `BatchMode=yes` (никаких запросов пароля) и `StrictHostKeyChecking=accept-new`: ключ нового сервера запоминается при первом подключении, а если он потом сменится, туннель не поднимется.

## Разработка

```
core/           прокси, провайдеры, OAuth, роутинг, журнал запросов, геопроверка
cli/            бинарник claude-bridge
ui/             Flutter-приложение
ui/native/hub   Rust-часть UI на rinf (акторы поверх core)
```

```bash
cargo test --workspace
cargo clippy --workspace --all-targets

cargo install rinf_cli --version 8.11.0   # один раз
cd ui && rinf gen                          # Dart-биндинги не хранятся в git, их генерирует rinf
flutter run -d linux                       # или macos / windows
```

Если поменялись сигналы в `ui/native/hub/src/signals`, заново запустите `rinf gen`.

## Релизы

[`.github/workflows/release.yml`](.github/workflows/release.yml) собирает CLI и UI под Linux x64, macOS (universal) и Windows x64 и публикует GitHub Release с именем, равным версии.

1. Закоммитьте изменения и выполните:
   ```bash
   scripts/release.sh 0.2.0
   ```
   Скрипт поднимет версию в `cli/Cargo.toml`, закоммитит её и отправит коммит вместе с тегом `v0.2.0`, поэтому тег всегда стоит на коммите с нужной версией.

Тег должен совпадать с версией в `cli/Cargo.toml`, иначе сборка остановится. Пересобрать существующий тег можно через «Run workflow» во вкладке Actions.
